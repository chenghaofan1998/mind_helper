# UI 生图与视觉探索 Brief

## 1. 结论与使用顺序

**P0 的记入、查询、原文结果、危险复制确认已有 10 张旧色探索图，不继续扩展知识中台。** 这些 PNG 生成于蓝灰 token 更新前，不属于当前视觉链，也不能直接作界面或文案验收基准；当前颜色以本文件色板、`gpt-image-2-prompts.json` 与 `ui/*.svg` 为准。

生成前依次阅读：

1. [`../docs/ACTION-POCKET-CHARTER.md`](../docs/ACTION-POCKET-CHARTER.md)：产品定位与信任红线，优先级最高。
2. [`IMPLEMENTATION-NOTES.md`](IMPLEMENTATION-NOTES.md)：按阶段缩减范围；与纲领冲突时不能覆盖纲领。
3. 本文件：逐图纠偏、布局、状态、文案与生成验收规则。
4. [`PRODUCT-FLOWS.md`](PRODUCT-FLOWS.md)、[`SCREENSHOT-AND-VISION.md`](SCREENSHOT-AND-VISION.md)：流程参考，未来设计不等于本轮需求。

图像用于评审布局和状态，不证明功能已实现。旧 `ui/*.svg` 也须通过本次规则核对，不能因“可编辑”就视为正确。

### 已发现的规划冲突

| 冲突 | 本轮生成口径 |
|---|---|
| 历史稿将“固定 / 有用”列为首版操作，但真实反馈确认其拥挤且无消费工作流 | 删除结果卡“固定 / 有用”和固定列表；旧存储仅作清理兼容，不展示 |
| 实现注记称 03 必须严格实现、04 整张保留，但成图含错误文案、派生层和大型后台 | 只保留原文优先与安全确认原则，不照搬整图 |
| 截图文档同时出现遮挡编辑、双模式按钮与简化链路 | P1 仅做选区、预览、重选和显式发送；不画遮挡编辑器、双模式或区域引用，敏感内容需先在源界面处理或重选 |
| “单一发送并查询”与“模型建议问题经用户确认后送知识库”存在时序冲突 | 不让一个按钮跨过文本确认；P1 分成发送截图分析、确认问题查询两个连续状态，每个状态只设一个主按钮 |
| 文档写 Windows/macOS、始终置顶，纲领要求按设备确认、必要时置顶 | 本轮统一 Windows 视觉变体，仅为设计基准，不承诺双平台交付；置顶是可切换状态，不预设永久开启 |

尚未由上位文档决定的产品边界，先确认再生图，不让模型自行补齐。

## 2. 历史 v1 成图评审：问题 → 后续约束

以下观察对应已移除的历史 v1 01–10 原图。原图不再保留，但问题记录继续约束下一次按当前 token 生成的状态图及后续实现。

| 原图 | 可见问题与影响 | 下一轮必须修改 |
|---|---|---|
| 01 快速记入 | 大标语、图标和置顶开关占用输入空间；保存热键画成 `Ctrl+Shift+S`；写入目标偏重，`68 / 2000` 引入未定义限制 | 删除标语区；固定 `Ctrl+Enter`；目标用一行“知识源 · 位置 · 更改”；不凭空加字数上限；补失败保留全文状态 |

| 03 结果 | `pages/Adam.md` 内却是 Action Pocket 截图说明；版本 `v1.4.2` 与应用页脚混淆；大“查询意图”和派生提示抢占原文；出现 `Win+Shift+S` 和“没解决” | 查询、原文、定位、版本必须来自同一份示例；删除意图/检索模式大卡与派生层；只保留复制原文/命令和打开原文/复制定位两类操作 |

| 05 截图选区 | 工具栏带本轮不做的遮挡编辑；“使用此截图”是否上传不明确；“此截图不会被永久保存”未区分本地与提供商 | P1 用“重选 / 取消 / 使用截图（进入预览）”；选区确认不上传；本地生命周期和远端保留政策分别说明 |
| 06 截图分析 | 05 是登录报错，06 却变成项目进展图；缩略图过大；“截图观察”实际只有图片，状态不清；加入快捷问题、双模式按钮；虚构“仅本地分析”“默认 30 天”“不用于训练”“企业安全合规” | 延续同一截图；分清预览与模型返回状态；缩小预览；每状态一个主操作；提供商、处理位置、保留策略必须有依据，无依据写未知而非保证 |
| 07 后台连接器 | 六项导航、三类连接器同时铺开；将 Graph 解释为构建关系图谱；“云端 / 本地”并列不能说明当前去向；缺少直接可用的地址、默认写入位置、测试入口 | 仅一页、一个当前知识源，展示名称、地址、写入位置、测试结果；能力只读；Graph 不等于要建设知识图谱；不展示未验证的企业能力 |
| 08 热键形态 | 文案称截图完成后“自动保存或进入下一步”；设置中出现“监控键盘（全局快捷键）”，与无键盘钩子说明冲突；小窗变成另一种横条形态 | 仅作文档；截图后进入本地预览，明确不自动保存/上传；全局热键注册不称为键盘监控；示意小窗沿用 P0 外壳 |
| 09 未来观察 | 出现“首页 / 专注 / 统计”新导航；持续显示托盘状态被画成可关闭开关；开始按钮使未来能力像已可用功能 | 本轮不生成、不放入产品导航；未来独立评审时运行状态必须持续可见、不可关闭，停止必须是可用操作而非说明文字 |
| 10 架构图 | 增加企业 SSO、IM、日历、SaaS 等未验证能力；“模型观察”被解释为监控模型行为，与截图观察混淆；三类输出等权 | 仅作文档且区分当前/未来；只画已约定数据流；模型观察是截图推断，不是模型监控；不将能力字段翻译成新增页面 |

### 跨图共性问题

- **产品身份漂移**：叶子、豆形、字母 A 等 Logo、标语、窗框和导航反复变化。统一一个简单 AP 字标，不在逐页生成时重新设计品牌。
- **同色不等于同一产品**：统一外壳、字号、间距和控件位置，不能仅要求“深石板、高级感”。
- **状态覆盖不足**：多数只画填满内容的成功态，没有可靠写入、检索失败、来源失效和复制失败的恢复路径。
- **尺寸概念混淆**：PNG 输出画布不是产品视口；不能靠扩大页面塞进所有信息，再宣称它是 560×680 小窗。
- **提示词本身在扩张范围**：旧提示词要求三层输出、负反馈、六项后台导航和未来观察；仅修 Brief 不会自动改变生图脚本的输入。

## 3. 范围与页面契约

### P0：本轮生成

| 页面 | 唯一主要任务 | 必须出现 | 不得出现 |
|---|---|---|---|
| 01 记入 | 将原始文字写入明确知识源 | 原文输入；知识源与写入位置；更改位置；保存；回执/错误位置 | 整理向导、分类/标签必填、附件、自动改写、字数上限 |
| 02 查询 | 用当前问题找回旧内容 | 一个问题框；查询；单来源与真实模式一行状态 | 综合回答、模型/排序/检索参数选择器、热门问题卡 |
| 03 原文结果 | 找到可直接使用的一段 | 少量结果，最多 5 条、默认展开 1 条；原文与必要上下文；来源定位与版本；复制及安全打开/定位 | 无证据的新解释、派生提示大卡、相似度条、追问聊天、固定与反馈 |
| 04 危险复制 | 知情确认后只复制 | 同一结果页背景；完整命令、来源、具体影响；取消、仍然复制；可见焦点 | 执行/运行按钮、绿色“安全命令”评级、按 Tab 直接复制 |

后台设置是一个独立的原生 WinForms 设置窗口，不是主窗内新增导航：主窗只切换已配置项目并完成记入/查询，设置窗负责项目清单、添加文件夹、添加单个 `.md`/`.markdown`、把文件夹标记为 Markdown 或 Logseq、重命名、删除（删除最后一项需二次确认）、设置默认项目，以及保存/取消。本轮默认提示词先聚焦上述四个任务。

### P1 / P2 / 归档：不混入 P0

- **P1**：05/06 一次性截图链路。在 P0 验证后单独批准生成，不能在 P0 小窗塞入可用截图入口。
- **P2**：遮挡编辑、Derived 渲染、负反馈等需真实需求支撑。当前项目切换因真实反馈进入 P0；固定与有用不展示。
- **文档与归档**：08/10 是说明图，不是产品页面；09 未来观察本轮不生成，不放灰色占位导航。

P1 的状态顺序必须明确：

```text
显式热键 → 选区 → 本地预览 + 可编辑问题
  → 展示接收方/图片范围/保留策略 → 用户“发送截图分析”
  → 模型返回“截图观察（模型推断）”和建议问题
  → 用户修改/确认文本 → “查询知识库”
  → 原文证据（视觉主位） + 临时模型观察（次位）
```

两次发送各有明确接收方；原图默认不送知识库、不自动写回。用户取消时销毁本地会话图像；已经发送的数据不能声称通过本地取消就从远端删除。没有分析能力时明确禁用入口并说明原因。

## 4. 固定外壳与视觉参数

以下是本轮设计约束，不代表已经实现的跨平台能力：

- 产品视口：小窗 **560×680**，包括标题栏；后台 **1280×820**。危险模态在小窗内，不能切换成全尺寸管理台。
- 生成画布：正式使用 OpenAI `gpt-image-2`，高质量 **1536×1024 PNG**。小窗完整居中、保持 560:680 比例，等比放大或留白，禁止拉伸填满横画布。
- 标题栏 40px；“记入 / 查询”切换区 40px；页脚操作区 56px；主体内边距 16px。信息超出时仅主体滚动，主操作与错误摘要仍可找到；不扩大视口、不无限缩字。
- 外壳分三段：固定顶部（项目切换 + 输入）、中间唯一滚动主体、底部固定操作区；不得让整个输入面板与按钮共用一个滚动容器，也不得用 `margin-top: auto` 推按钮。结果卡操作使用稳定 grid：复制/打开两项同高同宽，窄窗口可整齐纵向，不用 `margin-right: auto` 混排。440×560 与 560×680 两个尺寸都要成立。
- 只有“记入 / 查询”两个意图入口。结果仍属于查询；危险确认仍属于结果。设置用一个次要入口，不另造知识库、笔记、灵感、精选、统计或历史模块。
- 保留 AP 字标、Action Pocket 名称和可拖动 header；使用透明无边框 Neutralino，不显示或仿制 Windows 最小化/最大化/关闭控件。仅保留可访问的窗口置顶操作。
- 色板（Today AI 白玻璃参考，已核对官网真实 HTML/CSS）：header 不再使用深色条；主壳白色 ~70%、`backdrop-filter: blur(10–16px)`、圆角 24–28px、白色内高光与柔和大阴影；背景只保留非常轻的浅蓝 `#b7ddfb/#dfeafd` 到暖桃 `#ffe2c3` 的漫反射，不做显眼彩色块。输入、项目切换、结果卡同属玻璃层级（white/45~72 与低对比细边框），正文保持足够对比，危险态仍用红 `#C54B43`。主按钮用深色/近黑，避免整页蓝色。header 文字 black/65；深色只用于小面积主按钮。Windows 11 Mica / Windows 10 Acrylic 继续作为 OS 背景层，失败时回退不透明白色。
- 字体：中文优先思源黑体或系统无衬线；正文 14px/22px，辅助 12px/18px，页标题 18px/26px；命令使用等宽字体。
- 间距以 8px 为主；容器圆角 12px、控件 8px；控件高度 32–36px；线性图标 16–20px。少量阴影，不用大插画、标语卡和渐变装饰。
- 普通文字对比度目标 ≥4.5:1，焦点/控件边界 ≥3:1；状态同时使用文字，不只依赖红绿颜色。实际值由结构稿/组件测量，不能凭 PNG 声称通过无障碍验收。
- 原文是主体，不把正文排成代码行；行号/块定位放在来源区。只有真实命令使用代码块，长命令可横向滚动，复制内容不得被省略号截断。

## 5. 文案与示例数据：先锁定，再生成

### 固定语义

- 保存：`保存到知识库`，快捷键 **Ctrl+Enter**。只有收到知识源回执才能显示“已保存”；失败必须保留全文。
- 查询：**Enter** 提交；`↑↓` 选择结果；结果态 Enter 触发当前明确标出的主操作，危险内容先进入确认。
- 普通入口 **Ctrl+Alt+P**；P1 截图入口 **Ctrl+Alt+Shift+P**。不得替换为 Ctrl+Shift+S、Win+Shift+S 或 ⌘K。
- **Esc** 优先取消模态并恢复原焦点，其次取消截图，再隐藏小窗；不能写成一律退出程序。静态图只展示提示，实际行为需交互验证。
- **Tab / Shift+Tab** 只切换焦点；危险模态默认焦点在取消，显示明确描边。复制失败不显示成功、不自动关闭。
- 检索模式保留在 descriptor/可选 tooltip 中，不以长文案或卡片占据结果空间。没有健康/索引新鲜度数据时不凭空显示状态。
- 来源定位按知识源提供的路径+行号或页面+块标识展示，不要求所有来源伪造行号。来源版本与应用版本不得混用；缺失写“来源未提供版本”。
- 云端/本地处理、保留时间、是否训练等只复述有依据的策略。不得自行承诺“企业安全合规”“只本地处理”“30 天”“永不保存”“不用于训练”。

### 连续示例（均为设计样例，不冒充真实检索回执）

| 示例 | 问题/内容 | 统一来源 |
|---|---|---|
| 记入 | “我把 Adam 的一阶矩理解为：给最近的梯度多一点权重，让更新方向不被单次波动带偏。” | 个人知识库 · `pages/Inbox.md`；写入成功图需带示例回执定位 |
| 概念查询 → 结果 | 问题：“我以前怎么理解 Adam 的一阶矩？” 原文：“我把一阶矩理解为最近梯度的加权平均：像带记忆的方向，最近的梯度权重更大。它不是完整的 Adam；二阶矩还用于调整更新尺度。” | `pages/Adam.md` · 第 120–122 行 · 来源版本 `rev-adam-01` |
| 命令结果 → 确认 | 问题：“把当前分支退回前一个提交，放弃已跟踪文件的本地修改。” 命令：`git reset --hard HEAD~1` | `pages/Git.md` · 第 40–44 行 · 来源版本 `rev-git-01` |
| 命令风险说明 | “当前分支将退回前一个提交，并丢弃已跟踪文件在暂存区和工作区的未提交修改。Action Pocket 只会复制，不会执行。” | 模态与背景使用同一命令、来源和版本；不声称已替用户检查或备份仓库 |
| P1 截图连续性 | 05 与 06 使用同一 `401 Unauthorized` 登录报错截图；问题围绕该错误，不跳成项目报表 | 模型只描述可见事实，不从截图断言真实根因或编造知识库命中 |

示例身份在配套说明或画布外标注，不向小窗塞大量自证标签。没有提供的事实不生成；不匹配的文件名、行号、正文、版本或数据去向均判为不通过。

## 6. 状态覆盖与输出清单

同一任务的状态要拆图，不在一张“万能画面”同时画未提交、分析完成和成功结果。

| 页面 | 完整主态 | 必须补充的关键状态/交互说明 |
|---|---|---|
| 01 | 已输入，等待保存 | 保存中禁重复提交；保存成功有回执才清空；保存失败保留同一全文；无可写来源禁用保存并给设置入口 |
| 02 | 已输入，等待查询 | 查询中；无结果且保留问题；来源不可用/超时且可重试；诚实的词法模式 |
| 03 | 概念原文与必要上下文 | 命令结果；来源更新/删除/无权限；复制成功/失败；安全打开与复制定位降级 |
| 04 | 危险确认，取消获焦 | Tab/Shift+Tab 焦点循环、Esc 返回原位置的交互标注；复制失败留在模态并可重试；复制成功仅提示已复制 |

本轮 `gpt-image-2-prompts.json` 提供四个主画面及高风险关键状态的独立输入；其余状态先在结构稿/交互标注补齐，不以一张成功图替代完整验收。

每组交付：

1. 完整窗口 PNG + 至少一张关键状态图；局部评审可从已核对的完整状态图裁切，不另生一个风格不同的局部。
2. 对应可编辑 SVG/Figma 结构稿，保留实际视口尺寸、滚动区域、焦点顺序和错误反馈位置。
3. 配套记录：阶段、页面、状态、版本、示例数据、提示词、参考图、评审结论。图片不得独自承担交互规格。

## 7. 提示词与生成执行
