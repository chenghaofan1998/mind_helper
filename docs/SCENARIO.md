# Command Pocket · 场景交付：「推不上去的那三秒」（执行型命令终端）

> 本文回答三件事：① 一个具体场景；② 围绕该场景的解决方案（链路每一环：技术+要解决的问题）；③ 让这个场景真正成立，还需要做的全部准备。
> 由来：经历"答案抽屉 v2 → 反射终端 v3 → 零监听裁定 v3.2"三轮后，用**卡点对账法**反推（C1 唤起漏斗 / C2 验证黑箱 / C3 供给侧），唯一能让三条卡点同时成立的形态＝**执行型命令终端**：Enter=执行、退出码自动回写、历史自动种库。本文即该形态的场景化交付。

---

## 一、场景（三秒，能演出来）

> **周五 17:55。你把改动推上去，被拒了。**
> `git push` 报 `! [rejected] non-fast-forward`。你知道要 rebase 或 force-with-lease，但记不清确切写法——更不敢乱敲 force，怕把同事的提交冲掉。

```
① 你按一下 Ctrl+Alt+P（就这一个键，不用记别的）
② 弹出候选，第一行写着：
   ▶ git rebase -i HEAD~1       上次成功 · 用过 12 次 · [安全]
   ▶ git push --force-with-lease origin main   上次成功 · 用过 3 次 · ⚠风险3
   ▶ git log --oneline -5       最近在用（兜底，永远有货）
③ 你选第 2 条 → Enter（直接执行，不是复制粘贴）
   → 弹确认条，全文展开：git push --force-with-lease origin main
   → 3 秒内你按 Enter 确认 / 超时或 Esc 自动取消（误触零代价）
④ 退出码 0 → 右下角灯闪一下"成了"，这条自动加分，下次排更前
   退出码非 0 → 自动记一次失败并降权，右下角提示"要不要把这次报错存成卡"
⑤ 全程零监听：它看的只有你自己账上的数据（用过几次/上次什么时候/上次成没成）
```

为什么是它：**高频**（git 类命令天天用）· **可验证**（退出码天然可观测）· **安全门有真用武之地**（危险命令恰恰是"不敢乱敲"的痛点）· **能自举**（成败自动回流，不用你手动反馈）。

## 二、解决方案（链路每一环：问题→做法→技术）

| 环 | 要解决的问题 | 做法 | 技术/落点 |
|---|---|---|---|
| 1 唤起 | 记不住快捷键的人记得按什么？ | **只有一个键** Ctrl+Alt+P（沿用现有）+ 托盘；首启 60 秒演示养出第一个正反馈 | RegisterHotKey（S0 补返回值检查） |
| 2 候选 | 弹哪几条？不看用户输入怎么"猜得准" | 排自己的账：频率×近因×成功率×场景种子。失败≥3 且成功率<40% 自动降权；无数据时退回"最近再用"兜底，永不空屏 | 复用 RecScore 改造；新事件源＝退出码 |
| 3 动作 | 复制还是执行？ | **默认 Enter=执行**（唯一可验证出口）；Ctrl+Enter=仅复制（保守通道永远在） | SkillRunner（Process+退出码+超时） |
| 4 安全 | 执行不吓人、误触零代价 | 危险分级 0–4 + 确认条全文展示 + **3 秒超时自动取消** + 见习期（新命令前三跑强制预览） | 静态危险词检测作独立二道闸 |
| 5 验证 | 怎么知道"真管用" | **退出码自动回写** stats(exec/suc/fail)——零监听下唯一的自动观测点 | BumpExec 批量写（S0 基建） |
| 6 沉淀 | 库怎么越来越像你、不腐烂 | 成功上浮/失败下沉/30-60-90 遗忘照旧；**"这次报错没解决"一键存卡**＝供给口子 | 试用态字段（纯追加） |
| 7 反馈可见 | 系统做了什么要能被你看见 | 托盘灯闪＝成功；状态栏"基于 12 次成功执行排序" | 审计 jsonl（本地） |

北极星（可自证版）：**有唤起且有执行动作的 Top3 采纳率 ≥60%（样本 ≥50 才亮灯）**；辅以退出码分布、Esc/超时取消率。复制不算采纳——只有执行/明确复制才算，粘贴不可观测的部分不假装知道。

## 三、准备（让这个场景成立，还必须做这些）

### A. 数据准备
- **种子命令库**：预置 20–30 条高频安全命令（git/pwsh/常用工具，带风险分级与副作用声明），其中 2–3 条刻意演示危险门（force-with-lease/reset --hard），保证冷启动第一天就有货、就有一条能跑通完整闭环；
- **历史导入**（只读、预览、勾选）：PSReadLine `ConsoleHost_history.txt` → 去重 Top-N → 全部进试用态；password/token/私钥行禁选（脱敏正则）；
- **schema 升级与迁移**：卡片加 `risk(0-4) / sideEffects / stats(exec,suc,fail) / lastExecAt / lifecycle`——纯追加字段，旧程序读新库不崩（读卡宽容已验证）。

### B. 基建准备（S0 三件套，任何路线都要先还的债）
- 热键返回值检查＋为 Ctrl+Alt+Enter(仅复制) 预留第二热键；
- CommandStore 批量更新（退出码回写高频，不能碎写盘）；
- **危险确认门**：现在代码 `CopySelected` 直写剪贴板、风险标注不拦截——它是执行安全的命门，必须先补。

### C. 安全准备（执行的命根子）
- 分级确认：0–1 一键过 / 2 写文件预览 / 3 改配置+联网二次确认 / 4 不可逆手输确认词＋影响清单；
- 静态危险词检测（rm -rf / drop / format…）独立于任何模型；
- 新命令"见习期"：前三跑强制预览逐条审计；
- 执行超时＋可 Kill＋异步读管道（防假死锁）；审计只追加不覆盖；
- **自证材料**：单文件、无网络、默认零监听——发布前跑 Defender/多引擎预检，规避杀软误报。

### D. 习惯与信任准备（非代码，但决定成败）
- **首启 60 秒**：托盘闪一次 → 引导按热键 → 执行一条只读命令（git status）→ 看灯闪＋成功计数——第一次"被真帮到"胜过一切教程；
- 反悔三层（托盘第一组）：场景静音 / 暂停执行建议（退纯搜索）/ 退出；误触成本压到 0 用户才敢用执行；
- 只在终端/命令行场景唤出候选（场景标签），不打扰其余工作。

### E. 验证准备（让"可行"成为可证伪的）
- SelfTest 扩充：假时钟（61 天衰减）、假命令夹具（可控退出码）、危险门用例；
- metrics 埋点：唤起次数 / 展示 Top3 / 执行采纳 / 退出码分布 / Esc·超时取消率——全本地；
- **2 周试点判定线**：有执行动作的 Top3 采纳率 ≥60%（样本 ≥50）＋ 日唤起 ≥3 次（连续两周）→ 过则加"报错即查"等第二入口；**不过则砍执行外的一切，锁死"纯搜索+最近再用"抽屉形态攒数据，v4 重审**。

### F. 边界准备（明确不做，防范围蔓延）
- 不可验证的知识（提示词/文档/攻略长卡）退回辅料地位，不做主场景——零监听下它们无自动验证环；
- 不做自动推送/常驻剪贴板/原地注入（出局理由见 v3.2 裁定）；
- "通用知识库输出终端"愿景存档：先走通执行闭环，再谈接入更大知识体（届时需先补 AI 客户端，配 key 可选）。

## 四、卡点对账（证明不是拍脑袋）

| 卡点 | 本方案 | 判定 |
|---|---|---|
| C1 唤起漏斗 | 一个键＋高频正反馈＋首启演示；仍要求养成习惯，但回报密度最高 | ◐ 缓解（诚实标注） |
| C2 验证黑箱 | **退出码自动回写**＝零监听下唯一自动观测 | ✓ 解决（限执行类） |
| C3 供给侧 | 历史直接种库＋种子兜底＋失败一键收录＋执行自举 | ✓ 解决 |
| C4 匹配质量 | 随 C2/C3 水涨船高（成功率进排序） | ○ 半卡点 |

剩余弱点与反制：① 习惯养成仍需时间 → 60 秒首演＋演示种子；② 只覆盖可执行知识 → 边界 F 已声明；③ 执行有风险 → 安全门 S0 前置、3 秒超时、见习期。

| 步(周) | 交付 | 过/不过 |

| **M1(1–1.5)** | 执行器 SkillRunner＋分级安全门＋退出码回写＋审计 | 危险门 100% 拦截；假命令夹具可控退出码通过 |
