# Action Pocket 模拟试点报告（04）

> ⚠️ **诚实边界（必须读）**：本文全部“团队、Runbook、时长、意愿、付费意向”均为**模拟值**：
> - “机制项”（解析、批准、运行、续做、过期、流水、敏感参数、确认门）由脚本**机械实测**；
> - “体验项”（基线/用时下降、重复使用、付费意愿）为**模拟专家估计与意愿设定**。
> 本文只证明“机制跑得通、验收口径可量化”，**不构成产品成立的市场证据**。真实阶段 0（5 个真实团队 + 真实 Runbook）仍待补齐。

## 一、执行方法

- 复用 5 份模拟 Runbook（`actionpocket/fixtures/teams/*/runbook.md`，见 `03`）。
- 用同一套引擎（actionpocket）跑完整旅程：`draft → approve → run → 逐命令复制 → 勾选 → 完成`；另跑 J2（源变化过期）与 J3（owner 驳回重提）。
- 复现命令：`npm run ap:simulate`（输出即本文数据来源）。

## 二、各队执行摘要（脚本实测 + 模拟口径）

| 队 | 草稿识别 | 步骤 | 命令复制 | 高风险确认 | 异常路径 | 结果 |
|---|---|---|---|---|---|---|
| A 商城发版 | 目标/适用/前置/参数/验证/风险全部识别 | 5 | 5 | 0 | J2：源变化→stale→拒运行→重批 v2 | ✅ completed |
| B 管道重跑 | 12 步全抽出；目标/适用/验证缺失并提示 | 12 | 4 | 0 | — | ✅ completed |
| C iOS 发版 | 参数表 5 项；api_key 判敏感 | 4 | 4 | 0 | 敏感凭据：不落盘、复制时逐次提供、流水无泄漏 | ✅ completed |
| D 数据库变更 | 3 项必填参数；步骤 2/3/5 判高风险 | 5 | 6 | 3 | 危险门逐条确认后才推进 | ✅ completed |
| E 工具升级 | 目标版本/当前版本占位符 | 4 | 3 | 1 | J3：owner 驳回→补参数默认→重起草批准 | ✅ completed |

关键观察：

1. **解析鲁棒性**：规整文档（A/D/C）与少章节口语文档（B）都能抽到有序步骤与来源行号；B 类文档缺“验证清单”被明确警告。
2. **只复制不执行**：全部命令仅经 `copy` 输出到复制区；`copyCommand` 事件不含命令正文。
3. **危险门**：D 的三处 `mysql <`（含 dry-run）与 E 的 `rm -rf`（在 /tmp 冒烟目录）都触发确认——**只判红不判绿**，宁严勿漏；dry-run 属可解释的保守误拦，由操作者确认放行。
4. **敏感参数**：C 的 `api_key/api_issuer` 不写入卡 JSON 的实例参数、不进事件流水；复制命令时未提供即拒绝，避免占位符被误复制。
5. **版本与过期**：批准记录批准人/时间/版本；源文件变化后卡片自动 stale、拒绝启动，重新批准升级到 v2 后恢复。
6. **人工闭环**：完成前必须有“验证项”（来自原文验证清单）；J3 演示了 owner 驳回 → discarded → 修正重提，草稿不能自行转正。

## 四、验证结论与限制

**机制层面可达**：纲领最小闭环（显式输入→解析→草稿→来源哈希→人工批准→参数→逐步复制与勾选→暂停续做→完成→流水→源变化失效）在本原型中全部走通，且被自动化测试覆盖（`npm run ap:test`，20 项全绿）。

**限制（不可逾越）**：

1. 全部“时间下降 / 意愿 / 付费”为模拟，非真实测量；
2. 无真实文档的措辞多样性压力（表格、代码、中英混排仅覆盖 5 个样本）；
3. 复制动作由 CLI 模拟，真实剪贴板与 Windows 托盘/热键外壳未在本环境验证；
4. 未验证多人协作下的“批准→分发→操作”真实摩擦。
