# Action Pocket 阶段 1 产品设计（模拟试点版）

> 前置说明：本设计依据 `docs/ACTION-POCKET-CHARTER.md` 执行。因当前**没有 5 个真实设计合作团队**，本次按发起人指示由实现者模拟 5 个团队跑通完整操作流。
> **诚实边界**：本文与 `04-simulated-pilot.md` 的一切“试点数据”均为模拟值，仅用于验证机制是否成立、流程是否顺畅、验收口径是否可执行；**不构成产品成立的市场证据**。真实阶段 0 仍待补。

## 一、产品定位（继承纲领）

指导性文本的行动层：把团队已有的 Runbook/SOP/Markdown 教程，在用户已决定执行时转换成**可核对、可执行、可暂停续做的行动卡**。北极星指标：行动卡被用于完成真实任务的次数。

## 二、首发场景与用户

- 场景：**重复发布与环境配置**（首发唯一场景，见纲领 §4.1）。
- 用户画像（模拟 5 队）：5–30 人小团队、有 Markdown Runbook、每周 ≥1 次重复流程、仍靠人工复制命令/填参数/核对。
- 介入时刻：用户已决定执行某发布/配置流程，准备打开文档逐步操作时。

## 三、模拟团队档案

| 队 | 团队画像 | Runbook 主题 | 文档风格特征 |
|---|---|---|---|
| A | 电商后端（Java/Docker，12 人） | 每周发版部署 | 规整章节：目的/适用/前置/步骤/验证 |
| B | 数据平台（Airflow/Python，8 人） | 数据管道重跑与排障 | 纯列表+命令混排，少章节 |
| C | 移动端（iOS/Android，15 人） | CI 签名与发版 | 含参数表 + 占位符 `{{}}` |
| D | 金融内部系统（.NET/SQL，9 人） | 数据库变更发布 | 高风险、含备份/回滚/干跑 |
| E | 内部工具组（Node，6 人） | 工具链升级 | 前置校验 + 逐版本升级 |

> 档案详表见 `03-simulated-teams.md`。

## 四、用户旅程（单机闭环）

```
显式输入(选文件/粘贴)
  → 解析(标题结构/有序步骤/代码块/占位符)
  → 行动卡草稿(目标/适用/前置/参数/步骤+原文摘录+行号/风险/验证)
  → 来源校验(文件哈希) + 规则检查(高风险步骤必须带来源)
  → 文档拥有者批准(记录批准人/时间/版本) —— 草稿不可直接成为正式卡
  → 参数填写(必填校验, 敏感参数不回显不落明文日志)
  → 逐步执行(每步: 步骤+来源定位+命令复制[只复制不执行]; 危险门确认)
  → 勾选/暂停/继续/完成验证
  → 结果记入本地流水
  → 源文件变化 → 卡置过期 → 重新批准
```

## 五、行动卡状态机（阶段 1）

```
draft ──approve──▶ active ──source changed──▶ stale ──re-approve──▶ active
  │                    │                              │
  └──(校验不过/owner驳回)─▶ discarded              archive(废弃)
```

- `draft`：解析产出的待核对稿，**不可运行**。
- `active`：owner 批准，记录 `approvedBy/approvedAt/version/sourceHash`。
- `stale`：源文件哈希变化后置过期；**过期卡不可启动新实例**，须重新批准。
- 运行实例独立于卡：`not_started → in_progress ⇄ paused → completed/aborted`。

## 六、阶段 1 P0 功能全集（由纲领 §6.1 展开）

| # | 能力 | 验收要点 |
|---|---|---|
| P0-1 | Markdown/纯文本解析 | 标题树、有序步骤、代码块命令、占位符参数、来源行号/摘录 |
| P0-2 | 行动卡草稿生成 | 目标/适用/前置/参数/步骤/风险/验证字段齐备 |
| P0-3 | 文档拥有者核对批准 | 草稿必须经 `approve` 才可运行；记录批准人/时间/版本 |
| P0-4 | 参数定义与填写 | 必填校验；敏感参数不回显、不入日志 |
| P0-5 | 步骤逐项复制与勾选 | 只复制不执行；每步来源可定位；可勾选完成 |
| P0-6 | 暂停与继续 | 任意步骤可暂停/续做，实例状态持久 |
| P0-7 | 原文引用与定位 | 每步存 `source.path + 起止行` |
| P0-8 | 来源变化过期提示 | 重哈希比对；过期卡禁启动 |
| P0-9 | 风险提示与完成验证 | 高风险命令执行前必须确认；验证步骤需用户确认 |
| P0-10 | 本地使用流水 | 事件追加式 jsonl；本地可见可删 |

## 七、明确不做（阶段 1）

同纲领 §6.2，并加：不做自动执行命令、不做账号/后台/同步、不做浏览器抓取/PDF、不做 RAG 检索。团队批准在本地以“批准后导出的卡文件 + 人工文件共享”完成（无账号约束下的最小分发，见架构文档 ADR-2）。

## 八、试点验收口径（模拟执行用）

继承纲领 §十并通过“模拟值”观察机制可达性：

- 开始正确第一步的时间下降 ≥30%（模拟对比基线）
- 完整流程完成率 ≥70%
- 无原文来源的高风险步骤 = 0（硬性，代码校验保证）
- 两周后重复使用团队 ≥60%、≥3 队愿意继续使用（模拟意愿）
- 至少 1 队含预算决策人的付费意向（模拟意向）

> ⚠️ 上述模拟结果仅证明“流程跑得通、口径可量化”，不能替代真实团队验证。
