# 老板打回决议 · Command Pocket v4 战略重想（RFP）

> 更新：本分支。由项目所有者（老板）签发的**打回决定**。打回范围 = 战略层（定位/场景/P0 形态/验错判据），**不涉及**工程资产。
> 被召集的思考者必须按本 brief 出提案；老板终裁前不写代码、不改现有 docs。

## 一、打回结论

> 现状 v4（`docs/PRODUCT.md`）在**工程上**无可挑剔：数据模型、宽容读写、加权检索、危险确认、自测纪律都成立。
> 但它在**战略上**是"命令记忆抽屉 2.0"——一个正面撞成熟竞品、无不对称优势、且把唯一差异化方向自我后置的方案。作为老板，判定：**P0 定位被打回，重想后再议。**
> 这不是对执行的不满，是对"这个产品凭什么存在"的回答不满意。

## 二、打回依据（四条，引用即用）

1. **夹在产品与工具之间**：叙事想当"产品"（多 PM/裁判式评审/北极星），形态却是被 Raycast/Alfred/espanso/uTools 做烂的"热键小窗+搜索+复制"抽屉，功能量级远不及竞品，无生存位。
2. **唯一差异化被自我后置**：v3.2 曾提出"出错现场的第一站/报错即查"（用户卡在 git push 被拒、端口占用、permission denied 的那一刻），这是全部演进史里唯一不对称的位置；v4 却把它移出/后置，退回"用户得先想起自己有张卡"的回忆式抽屉。
3. **口径收窄自伤基数**：为躲开"AI 免预录即解 N1"（红队清单原句），收窄到"AI 答不出的私有命令"——但私有命令基数低，且强依赖用户先主动录卡（N2 冷启动命门），无卡源即"月开两次的抽屉"。
4. **闭环从未真机断过验证**：全部验证止于 Linux 容器内的静态审查与 Node 对拍；`dist` 里是可运行的 v0.4 旧版。北极星（采纳率 ≥60%、样本 ≥50）样本至今为 0。

## 三、老板的战略定性（重想必须在此框架内，或推翻它并给出更强论证）

- 定性：**个人效率工具**（服务老板本人 + 极少数同行），不按可规模化/可商业化产品立项。
- 已砍（不得复活，除非有压倒性新证据）：周姐"成品卡/分发"、跨设备、Logseq 双向桥（可作远期方向一句话带过，不进 P0）。
- 产品可做的前提只有一条：**冷启动不依赖用户先建卡**，或建卡摩擦低到行为成本趋近于零——重想必须直面这一点。

## 四、工程硬约束（重想必须遵守）

- 本地优先零监听无账号；数据纯本地 jsonl，可回滚。
- Windows 托盘 + 热键小窗形态可改，但保持 C# 单文件、纯 csc、无第三方依赖可编译。
- 不得引入常驻剪贴板/键盘监听（杀软误报 + 与木马行为同构不可自证，v3.2 裁定）。"显式触发读一次、读后即弃、零落盘"可讨论，但必须正面处理授权与自证问题。
- 存量资产可复用：CommandCard 模型（purpose/风险三件/rlabeled）、加权检索内核、DangerGuard 危险确认、SelfTest 骨架、scripts/spec-search.js 对拍台。

## 五、重想命题（每份提案必须回答）

1. 给谁，在**哪一天哪一秒**的真实时刻出现（写出分镜：此刻用户手边是什么、卡壳在哪、为何不会去开浏览器/AI/启动器）；
2. 凭什么 AI 对话与成熟启动器替代不了（或承认替代，给出躲开竞争的真正缝隙）；
3. P0 最小形态 = 用户动作流（从唤起到离开 ≤ 几步）；
4. 冷启动怎么解决（不靠"先记 20 张卡"的说教）；
5. 20 个真实用户日内可自证的验错判据（可证伪，不是口号）；
6. 诚实自纠：你的提案里最可能翻车的一点。

## 六、产出与流程

- 每份提案落盘 `docs/relook/<代号>.md`，中文，≤900 字（除红队路线论证 ≤1200 字），结构见 §五。
- 四路并行：A 止损派/最诚实路线 · B 钉子派/极致聚焦 · C 场景重构派/现场第一站翻案 · D 市场实证派/缝隙证据。
- 完成后由老板本人终裁：合并可行方向 → 写 `docs/relook/DECISION.md` → 若通过则作为 v5 规格前身，先在小范围真机试点，不再先写大文档。
