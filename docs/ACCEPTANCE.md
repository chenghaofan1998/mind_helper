# Command Pocket 验收手册（按真实使用流程走）

> 目标：像日常使用一样把整个链路走通。每步给操作 + 预期。全部符合 = P1 验收通过。
> 全程约 20 分钟。先花 1 分钟备份数据，坏了能回滚。

## 第 0 步 · 备份（必做，1 分钟）

```powershell
# 备份你的真实数据
Copy-Item -Recurse "$env:APPDATA\CommandPocketNative" "$env:APPDATA\CommandPocketNative.bak-v1"
# 确认里面有旧文件（你的真实历史数据）
Get-ChildItem "$env:APPDATA\CommandPocketNative"
```

## 第 1 步 · 编译 + 自动化自测（3 分钟）

```powershell
cd 你的项目目录（含 package.json 的目录）
npm run desktop
```

**预期**：
```
Built and verified dist-native\CommandPocketNative.exe
```
- 中间编译报错 = 失败，把错误贴回来
- 编译期间自动跑 7+ 组自测（HTML 清洗/抽取/双语搜索/存储往返/去重/复制统计/收藏推荐/v1 迁移），任何一组失败会显示错误并中断，把提示贴回来
- 注意：自测用临时目录，**不会碰你的真实数据**，放心跑

## 第 2 步 · 首次启动 = 你的数据自动迁移（关键，3 分钟）

双击运行 `dist-native\CommandPocketNative.exe`（或你原来的 exe 路径）。

**预期 1 — 无感迁移**：启动后像平时一样出现小窗。随后检查：
```powershell
Get-ChildItem "$env:APPDATA\CommandPocketNative"
```
应看到：
- `cards.jsonl`（新库，新格式）
- `cards.tsv.v1-backup-2026xxxx-xxxxxx`（旧库已改名备份）
- `profiles.json`（你的旧分类自动变成产品名单）
- 若你本来只有 seed 没真实数据，则直接生成预置卡（tar/git/docker/Codex/PyAgent/GTA 各若干）

**预期 2 — 卡不丢**：后台 → "已整理" → 数量应和迁移前一致（老卡都在，只是换个新家）。

**预期 3 — 老卡能搜**：小窗输入你以前存过的某条命令或中文关键词，能命中。

> 迁移只发生一次；之后再启动不再动 tsv 备份文件。

## 第 3 步 · 日常主循环（像真用一天，5 分钟）

1. **全局唤起**：切到任意软件（记事本/浏览器都行）→ 按 `Ctrl+Alt+P` → 小窗应出现在前台；再按一次 → 隐藏
2. **首屏有货**：刚打开不输入任何字 → 列表应直接显示"推荐"（不是空白）→ ↑↓ 选中第一条看明细 → `Enter` → 内容进剪贴板（粘贴到记事本验证）
3. **中文意图搜**（你最初的痛点）：
   - 输入 `压缩` → tar 那条应排第一
   - 输入 `撤销` → git reset 那条排前
   - 输入 `端口` → lsof 那条排前
4. **反向搜命令**：输入 `git reset --soft` → 能命中同一条
5. **切产品**：按 `` ` ``（Tab 上方那个键）→ 顶部下拉应在 产品间循环（Linux→Codex→PyAgent→…→全部），**列表内容跟随切换**，不会串产品
6. **推荐会被你的使用改变**：找到一张卡连复制 3 次（每次 Enter）→ 关闭小窗重开 → 该卡应在推荐里明显靠前
7. **收藏**：小窗右键菜单 → "已整理内容" → 选中某卡 → 编辑 → 勾上"收藏（推荐时优先）" → 保存 → 回小窗清空搜索 → 该卡应置顶

## 第 4 步 · 收录一条资料（像真遇到好东西，5 分钟）

打开小窗点"添加"（或托盘 → 添加资料），把下面这段**原样粘贴**进原料框，点"生成标准内容"：

```text
Linux 文件压缩速查
tar -czf archive.tar.gz folder
tar -xzf archive.tar.gz
注意：解压会覆盖同目录里的同名文件
找大文件：du -sh * | sort -h
```

**预期**：
- 右侧分栏出现：**左侧清单**列出生成的卡（类型不同颜色不同），**右侧是选中卡的字段表单**（一次一张）
- 左侧点哪张，右侧就显示哪张的全部字段（标题/别名/产品/类型/风险/收藏/正文/何时用/来源），可直接改，改完立刻同步
- 生成结果大致：`命令`×3（tar 压缩/tar 解压/du 排序）、`警告`×1、`文档`×1（摘要）
- **不会有**"docker 清理"那种中文行被误认成命令的卡
- 中缝可拖动调整左右宽窄；左清单右表单分栏跟随窗口宽度自适应
- "高级编辑…"可弹全屏编辑框做精细修改
- 确认入库 → 回小窗选对应产品 → 立刻能搜到刚入库的卡
- **产品隔离验证**：换到别的产品再搜它 → 应搜不到

可选：再贴一个网址点"生成"（走网页抓取）；或点"打开文件"选一个 .md/.txt（走文件读取）。

## 第 5 步 · 风险策略确认（1 分钟）

程序**不做任何自动风险判断或拦截**——复制任何命令都不弹确认，风险完全由你掌握。

**预期**：导入含 `rm -rf` 等内容的文本 → 生成的卡风险字段默认"低"；后台编辑某卡时可将"风险"手动标为高/极高（仅作信息标注，不影响复制）。你确认没有弹窗拦截 = 本步通过。

## 第 6 步 · 管理与备份（2 分钟）

1. 后台 → "管理产品" → 加一行 `我的测试产品` → 保存 → 小窗下拉出现它；用完删掉还原
2. 后台 → "已整理" → "导出" → 存一个 .jsonl 备份
3. 删掉刚才收录的那条卡 → 再点"导入备份"选刚导出的文件 → 卡片回来且不重复

## 第 7 步 · 看数据文件（1 分钟，确认没乱码）

```powershell
Get-Content "$env:APPDATA\CommandPocketNative\cards.jsonl" -TotalCount 2
Get-Content "$env:APPDATA\CommandPocketNative\profiles.json"
```

**预期**：每行一个 JSON 卡，中文明文可读（无乱码、无 \u 转义堆）；字段是 product/title/aliases/kind/body/desc/risk/copies 等；profiles.json 是 `["Linux", ...]` 产品名单。

2. 检查是否数据被破坏（对照第 0 步备份可回滚：把 .bak-v1 内容拷回）
